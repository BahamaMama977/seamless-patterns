# Периодическая сборка из мотивов

Адаптация идей воспроизводимости и управляемых параметров из `anthropics/skills/algorithmic-art`, изменённая для растрового принта 7 октября 2026 года. 8 октября добавлены рекомендации по тональным планам и непрозрачности мотивов. Атрибуция и Apache-2.0: [source-and-license.md](source-and-license.md). Код сборки написан независимо; p5.js и шаблоны источника не скопированы.

## Когда выбирать этот способ

Отдельные розы, листья, птицы и другие самостоятельные изображения удобно компоновать локально. Генератор отвечает за художественный вид мотивов, код — за их перенос через границы. Для цельной фактуры и взаимосвязанных контуров этот способ может менять художественную задачу; выбирай его по рисунку.

Сначала получи мотивы через встроенный ImageGen с настоящей прозрачностью. Просмотри каждый: объект должен быть целым, без обрезанных листьев, белой подложки, шахматной имитации прозрачности и нежелательного ореола. Прозрачный запас вокруг **исходного мотива** сохраняет весь силуэт; он не означает пустую полосу вокруг готового тайла. Сборщик удаляет только полностью прозрачный внешний запас.

Не получай прозрачность грубым удалением белого: так можно повредить светлые детали лепестков. Если подложка или обрезанный силуэт уже в файле, исправь мотив встроенным генератором. Художественная правка и механическая композиция — разные операции.

## Локальная конфигурация

Используй Python с Pillow. Запускай скрипт из папки скилла:

```text
python scripts/compose_pattern.py /absolute/path/layout.json --output-dir /absolute/path/print-v1
```

Пример `layout.json`; значения демонстрационные, а не настройки генератора, нормы печати или критерии качества:

```json
{
  "schema_version": 1,
  "width": 1200,
  "height": 1200,
  "background": "#FFFFFF",
  "seed": 42,
  "assets": [
    {"id": "rose", "path": "motifs/rose.png"},
    {"id": "bud", "path": "motifs/bud.png"}
  ],
  "layout": {
    "count": 24,
    "size_px": [180, 320],
    "rotation_deg": [-35, 35],
    "min_center_distance_px": 130,
    "max_attempts": 6000
  }
}
```

- `width`, `height`: размеры экспортируемого тайла в пикселях; определяй по задаче и фактическим возможностям локального рендера. DPI и размер печати согласуй отдельно.
- `background`: `#RRGGBB` либо массив `[R,G,B,A]`; прозрачный фон — `[0,0,0,0]`.
- `seed`: целое число для локальной раскладки. Он не воспроизводит генерацию мотивов в ImageGen.
- `assets`: локальные файлы; относительные пути считаются от конфигурации. Опциональный `sha256` закрепляет файл. Источники должны иметь реальную альфу, прозрачный внешний край и совместимые цветовые профили; сборщик отклонит несовместимые файлы с объяснением.
- `count`: количество самостоятельных мотивов на период. Копии через края не добавляются к этому числу. Вместе с размерами определяет плотность.
- `size_px`: диапазон максимальной стороны обрезанного по альфе мотива до поворота. Пропорции сохраняются.
- `rotation_deg`: диапазон поворота в градусах. Подбирай его по художественной задаче, особенно при заметном направлении света.
- `min_center_distance_px`: минимальное расстояние между центрами с учётом соседей через края. Это параметр раскладки, а не гарантия отсутствия пересечений сложных силуэтов.
- `max_attempts`: предел попыток разместить центры. Если запрос не выполнен, скрипт сообщает ошибку вместо молчаливого уменьшения числа мотивов. По умолчанию — `count × 200`, только локальный бюджет поиска.

Сборщик размещает центры по всей площади без защитного отступа от границ. Случайная раскладка может всё равно дать пустые полосы, сгустки или заметный период. Меняй параметры или конкретные координаты по результату просмотра; не считай любой seed удачным.

Для точной художественной раскладки вместо `layout` передай `placements`:

```json
"placements": [
  {"asset_id": "rose", "x": 0, "y": 0, "size_px": 260, "rotation_deg": 15},
  {"asset_id": "bud", "x": 620, "y": 470, "size_px": 190, "rotation_deg": -20}
]
```

Это фрагмент полной конфигурации, не самостоятельный JSON. `layout` и `placements` взаимоисключающие. Координаты — целые пиксели центров; значения за пределами периода нормализуются по модулю размера. Порядок списка задаёт слои: поздние мотивы перекрывают ранние.

## Тональные планы и непрозрачность

При работе по образцу сначала выполни [разбор референса](reference-matching.md). Получи и проверь значимые разновидности мотивов, включая бледные. Для контролируемого чередования и наложений используй явные `placements`; автоматический `layout` случайно выбирает файлы и не гарантирует присутствие каждого семейства, нужное соотношение планов или ритм образца.

Необязательное `opacity` в каждом объекте `placements` — число от 0 до 1, по умолчанию 1. Оно умножает уже существующий альфа-канал после размера и поворота, с округлением до ближайшего значения 8-битной альфы. RGB и исходный файл не меняются. При 0 мотив невидим; очень слабые детали могут исчезнуть из-за округления. На белой основе уменьшение непрозрачности делает мотив бледнее; на другом фоне вид будет другим. Проверяй результат на целевом фоне.

Например, если бледный и основной планы используют одну форму, можно повторно использовать один файл с разными значениями. Фрагмент `placements` для объекта с `id: "snowflake"` в `assets`:

```json
"placements": [
  {"asset_id": "snowflake", "x": 250, "y": 250, "size_px": 280, "opacity": 0.2},
  {"asset_id": "snowflake", "x": 700, "y": 650, "size_px": 300, "opacity": 1}
]
```

Значения демонстрационные, не измерения референса и не универсальные настройки. Для разных силуэтов, мазков или палитры используй отдельные файлы мотивов: прозрачность не исправляет художественную форму. Задние планы перечисляй раньше передних; не добавляй крупные фоновые фигуры, если их не требует рисунок.

Преобразованный мотив с заданной непрозрачностью применяется одинаково ко всем его переносам через края и углы. `opacity`, порядок и координаты сохраняются в `composition.json` и `replay-config.json`. Конфигурации без `opacity` сохраняют прежнюю непрозрачность. Поле относится к локальному сборщику, а не к генератору.

## Размеры объектов и зазоры

Для требования «без перекрытий» добавь необязательное поле верхнего уровня:

```json
"object_spacing": {"min_gap_px": 0, "alpha_threshold": 1}
```

`min_gap_px` — целое число от нуля: ноль запрещает пересечение силуэтов, положительное значение задаёт запас пустых пикселей между ними. Подбирай зазор по размеру печати, масштабу мотивов и запросу пользователя. Это настройка конкретной композиции, не универсальная плотность.

Сборщик проверяет реальные альфа-маски **после** смены размера и поворота. Прозрачные отверстия и участки внутри ограничивающих прямоугольников остаются доступными для других мотивов. Проверка учитывает перенос через все края и углы, а также соседние периодические копии самого мотива. Для положительного зазора используется квадратное расширение маски: по диагонали оно может оставлять больше свободного места, чем круговая мера расстояния.

`alpha_threshold` — целое число 1–255; по умолчанию 1, поэтому учитываются все пиксели с ненулевой альфой, включая полупрозрачные края. Повышай порог только намеренно, например чтобы разрешить наложение слабых теней. При таком пороге проверка не запрещает перекрытие пикселей, чья альфа ниже порога; не называй результат полным отсутствием перекрытий. Тонкие ореолы в мотиве исправляй художественно, если они мешают композиции.

При заданном `opacity` порог применяется к итоговой альфе после её умножения. Для намеренных наложений тональных планов не включай общий запрет перекрытий, если пользователь его не просит. Не повышай порог автоматически, чтобы обойти конфликт между запросом на зазоры и раскладкой.

При автоматической раскладке неподходящие позиции отклоняются в пределах `max_attempts`. При явных `placements` нарушение даёт ошибку с индексом объекта до сохранения результата; координаты не меняются скрытно. Невместимая композиция требует изменения размеров, количества, зазора или периода, а не молчаливого ослабления требования. Ограничение сохраняется в `replay-config.json`, а его проверка — в `composition.json`.

Без `object_spacing` перекрытия разрешены, поэтому плотные принты сохраняют прежнее поведение. `min_center_distance_px` можно использовать вместе с проверкой силуэтов для управления ритмом. Геометрический зазор не доказывает оптически ровных промежутков: итоговый повтор всё равно нужно просмотреть.

## Почему края продолжаются

Размер и поворот применяются к каждому мотиву один раз. Готовый растровый мотив рисуется во всех позициях `(x + kW, y + lH)`, которые пересекают тайл, с целыми `k` и `l`. Пересечение угла вызывает перенос по обеим осям. При больших мотивах вычисляются все нужные переносы, а не только ближайшие восемь соседей.

Все перенесённые копии одного мотива компонуются до следующего мотива, чтобы порядок наложений совпадал на границах. Размеры, повороты и альфа-смешивание допустимы при **создании конечного тайла**. После экспорта проверочное превью использует только точные копии готовых пикселей.

## Воспроизведение и проверка

Выход содержит `tile.png`, `composition.json`, `replay-config.json` и каталог `check` с точным превью и отчётом. Никакого автоматического вердикта о бесшовности нет.

`composition.json` фиксирует запрос, хеши мотивов, конкретные координаты, растровые размеры, хеши преобразованных мотивов, все позиции переносов, версию скрипта, Python и Pillow. `replay-config.json` использует конкретные координаты и закреплённые исходные файлы. Повторный запуск:

```text
python scripts/compose_pattern.py /absolute/path/print-v1/replay-config.json --output-dir /absolute/path/print-replay
```

Для воспроизведения нужны те же файлы мотивов и среда рендера. После переноса проекта обнови локальные пути, сохранив хеши. Один seed без мотивов, координат и версии рендера не обещает одинаковых пикселей.

Просмотри стыки, углы и распределение по [verification.md](verification.md). Если нужна интерактивная настройка, можно сделать локальную панель Canvas с параметрами и экспортом конфигурации, без CDN и сервисов. Сохраняй выбранные координаты; браузерный рендер может отличаться от Pillow. Для любого окончательного PNG вновь запускай точную проверку. Интерактивная панель не обязательна для обычной задачи.
